## 📚 문제별 토론 및 회고

### 📝 스위치 켜고 끄기
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/1244)
- **난이도**: Silver IV
- **주요 접근법 요약**: 
  - 스위치 번호는 1부터 시작하므로 내부 인덱스(0-index)로 변환 주의.
  - 0/1 토글: 비트 XOR(x ^= 1) 또는 산술(x = 1 - x)로 간결 처리.
  - 대칭 확장: left = idx-1, right = idx+1로 잡고 while로 경계/대칭 조건을 먼저 확인 후 확장.
  - 출력은 20개씩 줄바꿈; 언패킹/포맷팅으로 구현.
- **토론 내용 및 피드백**: 
  - while에서 “조건 확인→이동/토글” 순이 안전(인덱스 범위 에러 방지).
  - 현재 index를 즉시 바꾸기보다 “다음 index가 유효한지”를 확인하는 흐름이 버그를 줄임.
  - 나머지는 순수 구현 요소로, 케이스 분기 최소화가 핵심.

### 📝 자리배정
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/10157)
- **난이도**: Silver IV
- **주요 접근법 요약**: 
  - dx, dy를 따라 전진하다가 벽 또는 이미 방문한 칸을 만나면 방향 전환.
  - 전체를 다 채우지 말고, cnt==K가 되는 순간의 좌표만 출력해도 충분.
  - 시작 좌표 (1,1)이므로 visited 범위를 +1 해 index와 좌표를 일치.
  - C*R < K면 배정 불가(즉시 0 출력).
- **토론 내용 및 피드백**: 
  - 2차원 리스트에 값을 실제로 채우지 않아도 visited만으로 충분(메모리/시간 절약).
  - 단축평가로 덜 비용 큰 조건을 앞에 두면 분기에서 평균 시간 감소.
  - 완전탐색 우려가 있었으나, 방향 전환 시뮬레이션으로 K까지 효율적으로 도달 가능.

### 📝 AC
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/5430)
- **난이도**: Gold V
- **주요 접근법 요약**: 
  - R 명령 시 매번 실제로 뒤집지 않고 “뒤집힘 여부 플래그”로 상태만 관리.
  - D 명령은 플래그에 따라 앞/뒤에서 제거. deque의 popleft()/pop() 사용이 유리.
  - 빈 배열에서 D가 오면 즉시 에러 처리(Invalid).
- **토론 내용 및 피드백**: 
  - list.reverse()는 O(N)이라 누적 시 시간초과 위험. 상태 플래그 전환으로 O(1) 유지.
  - pop(0)은 O(N)이라 비효율적→deque 채택으로 popleft() O(1) 보장.
  - 최종 출력 시 플래그에 따라 방향만 결정해 직렬화하면 깔끔.

## 🚀 KPT 회고 (Keep, Problem, Try)
### Keep (유지할 점)
- 인덱스/경계 먼저 확인하고 상태를 변경하는 안전한 while 패턴
- 전체 연산 대신 “상태 플래그·단축평가”로 비용 최소화
- 출력 포맷(20개 단위 줄바꿈, 언패킹) 일관 적용

### Problem (개선할 점)
- 1-index ↔ 0-index 변환에서 간헐적 혼동
- 덱 등 적합한 자료구조 선택이 늦어지는 경우가 있음
- 빈 배열/범위 초과 같은 예외 처리 분기 누락 위험

### Try (다음에 시도할 점)
- 입출력 포맷 유틸 함수(20개 단위 줄바꿈, 배열 직렬화) 템플릿화
- “인덱스-경계-상태 전환” 체크리스트 만들어 구현 문제에 공통 적용
- deque(양끝 삭제), 투포인터, 슬라이딩 윈도우를 하루 1문제씩 루틴화
- 예외 케이스(빈 입력, 단일 원소, 최대/최소 범위) 미리 유닛 테스트로 검증
