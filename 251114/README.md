## 📚 문제별 토론 및 회고

### 📝 N과 M (4)
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/15652) 
- **난이도**: 실버 3 
- **주요 접근법 요약**:  
  - 1부터 N까지 자연수 중에서 중복을 허용해 M개를 고르되, 비내림차순(앞의 수 ≤ 뒤의 수)을 만족하는 수열을 모두 출력하는 전형적인 백트래킹 문제로 정리했다.  
  - 재귀 함수 인자로 `depth`와 `start` 인덱스를 두고, `for i in range(start, N)` 형태로 탐색해 중복 조합을 구현하고, 길이가 M이 되면 결과를 출력하는 방식으로 구성했다.
- **토론 내용 및 피드백**:  
  - 방문 배열이 필요 없는 중복 조합 패턴이라는 점을 다시 확인하면서, N과 M 시리즈에서 순열/조합/중복 조합을 빠르게 구분하는 연습이 되었다. 
  - 출력이 많은 유형이라 출력 버퍼를 사용하는 습관을 계속 유지하기로 했고, 백트래킹 템플릿을 공통으로 정리해서 이후 문제들에 재사용하자는 의견이 나왔다.

### 📝 과일 탕후루
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/30804) 
- **난이도**: 실버 2 
- **주요 접근법 요약**:  
  - 1부터 9까지의 숫자로 이루어진 수열에서, 서로 다른 숫자가 최대 두 종류인 연속 부분 수열의 최대 길이를 구하는 문제로, 투 포인터/슬라이딩 윈도우 대표 문제로 보았다.
  - 왼쪽·오른쪽 포인터와 각 숫자의 개수를 저장하는 배열/맵을 사용해 윈도우 안의 서로 다른 숫자 개수를 관리하고, 3종류가 되는 순간 왼쪽 포인터를 이동시키며 2종류 이하가 되도록 유지하는 \(O(N)\) 알고리즘을 사용했다.
- **토론 내용 및 피드백**:  
  - N 최대 200,000이라는 제한을 보고 바로 투 포인터를 떠올리는 패턴을 다시 확인했고, 처음에 구간을 직접 줄였다 늘리는 \(O(N^2)\) 방식과의 차이를 비교하며 시간 복잡도 감각을 정리했다. 
  - 과일 종류가 1~9라는 점을 이용해 두 숫자 조합을 고정하는 대안 풀이도 이야기했으나, 구현 단순성과 확장성을 생각했을 때 일반적인 슬라이딩 윈도우가 더 깔끔하다는 데 의견을 모았다.

### 📝 이중 우선순위 큐 다국어
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/7662) 
- **난이도**: 골드 4 
- **주요 접근법 요약**:  
  - 정수들을 저장하면서 최댓값과 최솟값을 모두 삭제/조회해야 하는 이중 우선순위 큐를 구현하는 문제로, 각 연산을 \(O(\log N)\)에 처리해야 하는 자료구조 문제로 분류했다. 
  - 최소 힙과 최대 힙 두 개를 두고, 인덱스나 값 기준으로 유효 여부를 기록하는 맵/배열을 사용해 lazy deletion을 구현하거나, 언어에 따라 `TreeMap`·`multiset`으로 한 번에 최솟값/최댓값을 관리하는 방법을 비교했다.
- **토론 내용 및 피드백**:  
  - 우선순위 큐 하나에 스택 또는 배열을 섞는 초기 아이디어가 시간 초과로 이어질 수 있다는 사례를 보며, 삭제 연산까지 모두 로그 시간 안에 처리해야 한다는 점을 다시 강조했다.
  - lazy deletion 시 서로 다른 힙 간 동기화가 어긋나는 버그(비어 있는 큐인데 값이 남아 있는 것처럼 보이는 문제)를 어떻게 테스트 케이스로 잡을지 논의했고, 유효 원소 개수 카운트와 최종 정리 단계 패턴을 정리해두기로 했다.

## 🚀 KPT 회고 (Keep, Problem, Try)

### Keep (유지할 점)
- 문제를 읽자마자 입력 범위와 연산 횟수를 먼저 보고, 가능한 알고리즘 후보(백트래킹, 투 포인터, 힙 등)를 먼저 좁혀 보는 습관을 유지하기로 했다. 
- 풀이 후 서로의 코드 구조를 리뷰하면서 함수 분리, 변수명, 자료구조 선택 이유를 말로 설명해 보는 흐름이 도움이 되어 계속 이어가기로 했다. 

### Problem (개선할 점)
- 유형을 알면 구현은 빠르지만, 처음 보는 문제에서 백트래킹/슬라이딩 윈도우/자료구조 문제라는 힌트를 캐치하는 데까지 시간이 조금 걸리는 부분이 있었다. 
- 이중 우선순위 큐처럼 복합 자료구조를 쓰는 문제에서, 경계 케이스(모두 삭제된 상태, 한쪽만 비어 있는 상태 등)를 충분히 체크하지 않아 디버깅에 시간이 길게 들어갔다. 

### Try (다음에 시도할 점)
- 같은 유형의 쉬운 문제(브론즈·실버 하위)를 1~2개 먼저 풀고, 그다음에 실버 2~골드 4 정도 난이도의 본 문제를 스터디로 가져오는 식으로 난이도 계단을 조금 더 세분화해 보기로 했다. 
- 제출 전에 각자 최소 3개 이상의 자작 테스트(최소/최대 입력, 비어 있거나 한쪽만 있는 케이스 등)를 만들고 돌려보는 시간을 의식적으로 확보해 보기로 했다.
