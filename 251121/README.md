## 📚 문제별 토론 및 회고

### 📝 N번째 큰 수
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/2075)
- **난이도**: Silver II 
- **주요 접근법 요약**:  
  - 입력받을 때마다 **힙(heap)**을 이용하여 큰 값 N개만 유지
  - `heapq.heappushpop()` 또는 `heapq.heappush()`/`heapq.heappop()` 활용  
  - **힙 크기 = N**을 유지하여 N번째 큰 수가 항상 힙의 최솟값 위치에 존재함  
  - 공간/시간 복잡도 줄이기 위해, 모든 값을 저장하지 않고 바로바로 비교/제거 진행
- **토론 내용 및 피드백**:  
  - 힙을 통해 불필요한 데이터 저장을 줄일 수 있다는 점이 핵심  
  - 메모리/시간 제한에 걸리는 문제 구조를 우선순위 큐로 깔끔하게 해결
  - 정렬 방식([heap])의 특성과, 힙의 크기가 곧 N번째 큰 수의 위치와 직결된다는 점을 체감

### 📝 한 줄로 서기
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/1138)
- **난이도**: Silver IV 
- **주요 접근법 요약**:
  - N 크기가 작으므로, 완전탐색과 단순 배열 삽입 가능
  - 매번 자리(인덱스)를 탐색하며 큰 사람이 앞에 몇 명인지 세서 삽입

- **토론 내용 및 피드백**:
  - 제한 조건(N≤10~20)의 경우, 성능 걱정보다 구현 정확성이 더 중요
  - 단순 배열 조작만으로도 충분히 풀리는 문제 구조
  - 반복적으로 자리 탐색하여 직접 삽입하는 과정 연습

### 📝 숨바꼭질 3
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/13549)
- **난이도**: Gold V 
- **주요 접근법 요약**:
  - BFS(너비우선탐색) 적용: 모든 가능한 경로를 '최단시간' 기준으로 완전탐색
  - 특정 조건(비용, 순간이동 등)만 잘 처리하면 BFS로 해결 가능
- **토론 내용 및 피드백**:
  - "의심하지 말 것": BFS는 항상 모든 경우의 수를 고르게 먼저 탐색
  - 시간초과 시에는 반복 구조나 큐 관리 방식의 문제를 점검해야 함
  - 다양한 BFS/우선순위 큐 문제에서 응용력 향상 필요

## 🚀 KPT 회고 (Keep, Problem, Try)
### Keep (유지할 점)
- 힙의 크기 유지, BFS 패턴 활용 등 효율적 알고리즘 선택 능력
- 단순 배열조작과 완전탐색의 적절한 적용

### Problem (개선할 점)
- 입력 처리/예외상황 처리에 더 빠른 자료구조의 도입 고민 필요
- BFS 활용시 visited(방문처리) 방법의 체계적 처리 연습 부족

### Try (다음에 시도할 점)
- 힙뿐 아니라 다양한 우선순위 큐 패턴 실습(최대/최소 힙 등)
- BFS 이외의 최적화 알고리즘(Dijkstra, DP 등)도 시도해보기
