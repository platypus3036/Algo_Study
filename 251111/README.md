## 📚 문제별 토론 및 회고

### 📝 마인크래프트
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/18111)
- **난이도**: Silver II 
- **주요 접근법 요약**: 
  - 가능한 최대/최소 높이 범위에서 역순 탐색
  - 2중 for문으로 각 높이에 대해 평탄화 했을 때의 소요 시간 산출
  - 인벤토리 블록이 음수가 되면 가지치기를 통해 불필요한 탐색을 차단하여 시간 최적화
- **토론 내용 및 피드백**: 
  - 가지치기를 적용하지 않으면 시간초과 발생, 효율적인 조건 처리의 중요성 확인
  - 모든 높이를 시도하는 완전 탐색보다는, 인벤토리 상태에 따라 불가능 조건을 빨리 차단하는 방법이 실전에서 유용함

---

### 📝 좌표 압축
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/18870)
- **난이도**: Silver II 
- **주요 접근법 요약**: 
  - enumerate로 인덱스와 값을 동시에 추출해 dict 등으로 저장
  - 단순 2중for문 사용시 시간초과 → 탐색(정렬/중복제거/매핑)을 2번으로 분리
  - 좌표 압축은 원소의 대소관계만 사용, 실제 값을 대신해 인덱스를 할당
  - map(dict)가 백만 단위에서도 빠르게 동작함을 실제로 확인함
- **토론 내용 및 피드백**: 
  - 입력 배열의 범위가 크거나, 불필요한 중복 데이터가 많은 상황에서 강력한 최적화 수단임을 체감
  - 실제로는 중복제거 → 정렬 → 매핑의 3단계가 핵심

### 📝 뱀과 사다리 게임
- **문제 링크**: [바로가기](https://www.acmicpc.net/problem/16928)
- **난이도**: Silver I 
- **주요 접근법 요약**: 
  - 최소 방문 횟수 산출을 위한 BFS 활용, 큐에 현재 위치와 count를 함께 저장
  - DP로도 시도했으나 뱀(내려가는 사다리)에 대한 처리 때문에 BFS가 더 적합
  - 최소 값/최대 값 교환·이동 횟수 문제에는 BFS가 강력함을 재확인
- **토론 내용 및 피드백**:
  - "최소횟수" 또는 "최단거리" 규명 필요 시 BFS 채택법
  - 방문체크/상태저장 등 BFS의 실전 팁 습득

## 🚀 KPT 회고 (Keep, Problem, Try)
### Keep (유지할 점)
- 조건 기반 가지치기, 입력의 대소관계 활용 등 효율적 탐색 방법을 잘 적용한 점
- 다양한 알고리즘 패턴(BFS, 좌표 압축, 완전탐색 등)에 직접적으로 도전한 경험

### Problem (개선할 점)
- 일부 문제에서 더 빠른 자료구조/알고리즘 선택을 못 한 점
- 코드 구조화/가독성면에서 개선이 필요함

### Try (다음에 시도할 점)
- 조건문과 반복문의 최적화를 자동화하는 방식 고민
- 단순 반복을 줄이고 효율성이 검증된 라이브러리 등 적극 사용
